# Agent File Write Approval

Date: 2026-06-05

## Problem

The agent's ReAct loop executes `write_file` tool calls by directly calling
`os.WriteFile()`, unconditionally overwriting files with no user awareness or
approval. Users are not informed what files are about to change, what the diff
looks like, or given a chance to reject a write.

## Goal

Before any file write operation by the agent, show the user a diff of the
pending change and require explicit approval (y/n) before the write proceeds.

## Non-Goals

- Auto git commit/checkpoint (deferred to a future iteration)
- Approval for non-file tools (`read_file`, `search_text`, `chat_llm`)
- `exec_command` approval (handled separately by SandboxDir)
- Session-level undo/redo

## Architecture

### Flow

```
User task → Orchestrator → Agent.Execute() → ReAct loop
  → LLM returns tool_call{name:"write_file", params}
  → Read existing file content (if exists)
  → Generate unified diff
  → Call ApprovalFn(path, oldContent, newContent)
    → TUI shows diff overlay
    → User presses y/n
    → Returns true/false
  → If approved: WriteFileTool.Execute() → os.WriteFile()
  → If rejected: return error observation to LLM
  → ReAct loop continues
```

### ApprovalFn Contract

```go
// ApprovalFn is called before a file write executes.
// It receives the tool name, parameters, old content (empty if new file),
// and new content. Returns true to proceed, false to abort.
type ApprovalFn func(toolName string, params map[string]interface{}, oldContent, newContent string) bool
```

### Where Approval Is Called

In `WriteFileTool.Execute()`, after parameter validation and sandbox checking,
but before `os.WriteFile()`:

```go
func (t *WriteFileTool) Execute(ctx ToolContext, params map[string]interface{}) ToolResult {
    // ... validate params, resolve path, check sandbox ...

    if ctx.Approval != nil {
        // Read existing content (empty if file doesn't exist)
        var oldContent string
        if data, err := os.ReadFile(path); err == nil {
            oldContent = string(data)
        }

        if !ctx.Approval(t.Name(), params, oldContent, content) {
            return ToolResult{Error: "file write rejected by user"}
        }
    }

    os.WriteFile(path, []byte(content), 0644)
    return ToolResult{Success: true, Data: fmt.Sprintf("wrote %d bytes to %s", len(content), path)}
}
```

### Propagation

The `ApprovalFn` must travel from the TUI layer to the tool layer:

```
TUI App (creates approvalFn closure that shows diff overlay)
  → main.go wires it into Agent.Config
    → Agent stores it
      → ReAct loop passes it into ToolContext.Approval
        → Tool.Execute() calls it
```

### TUI Diff Overlay

New file `internal/ui/approval.go`:

- A tview `Pages` overlay, shown when approval is requested
- Contains: file path, unified diff (colorized), y/n prompt
- Blocks the ReAct loop (waits for user input)
- Returns true (y) or false (n)

Diff is generated by a helper that compares old content vs new content,
producing a unified diff string. This diff is formatted with terminal colors
(green for additions, red for removals).
